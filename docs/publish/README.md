# 发布文案与平台检查表

本目录提供 Modrinth 与 CurseForge 的独立文案。项目页保持长期稳定：仓库同时发布
**Fabric 与 NeoForge**、**26.2 / 26.1.2 / 1.21.11** 多条线（见 [`../BRANCHES.md`](../BRANCHES.md)）。
Minecraft、加载器、依赖和发布阶段由**每个上传文件**的平台字段承载，不把单一版本或单一加载器写进项目标题、摘要或长期描述。

## 文件

- [`Modrinth.md`](Modrinth.md)：标题、摘要、描述和发布字段检查表
- [`CurseForge.md`](CurseForge.md)：名称、摘要、描述和审核检查表

## 两个平台都必须做到

1. 明确说明这是非官方社区移植，未获 MUKSC、TaCZ 团队或底层 Fabric 移植维护者背书；
2. 说明它不是原文件重传，并列出相较原版的实质性移植工作；
3. 正确选择 GPL-3.0，并保留原作者、上游项目和第三方资产署名；
4. 在每个文件的 metadata/Dependencies 中填写准确的游戏版本、**Fabric 或 NeoForge**、必需依赖和可选依赖；同一项目页可挂多条发行线的文件，但每个文件只对应一条线；
5. 项目描述不承诺所有第三方内容或可选模组都兼容；
6. 支持链接指向本仓库 Issue 模板，不把本移植问题转交给原作者；
7. 不提供未经许可的第三方枪包、贴图、模型、动画或音频；
8. 图标使用仓库内有来源和许可记录的原版图标。

## 发布前替换与检查

文案中的仓库链接已经指向本项目。若项目地址发生变化，应同时更新 README、Issue 模板和两站链接字段。

发布前执行：

```bash
python3 scripts/audit_port.py --strict
./gradlew build
```

然后确认：

- 项目名称没有游戏版本、文件版本或发布阶段；
- 摘要是单行纯文本；
- 没有把可选兼容写成硬依赖；
- 上传文件的依赖字段与 `fabric.mod.json` 一致；
- Source、Issues、License 和环境 metadata 均已填写；
- 项目页没有外部 jar 下载链接。

## AI 披露

这些发布文案使用了生成式 AI 辅助并由维护者复核。Modrinth 当前规则要求对使用生成式 AI 辅助的项目页作相应披露；发布者应启用平台提供的 AI content disclosure，并保留文案中的说明。不得使用 AI 生成或 AI 修改的项目图标、横幅或 Gallery 图片。

CurseForge 发布者也应如实遵循其提交时显示的最新披露字段。任何展示图片都必须准确反映实际游戏内容。
